# ADR-0007: الاختبار والبناء التلقائي (CI) على كل الأنظمة

- **الحالة:** مقبول (تم إعداد ملف `.github/workflows/ci.yml` — تُعتبر النتيجة غير مُختبرة حتى يظهر أول زر نجاح أخضر في GitHub)
- **التاريخ:** 2026-10-31

## السياق

قاعدة العمل تمنع دمج أي PR قبل نجاح كل الفحوص على كل الأنظمة. اليوم لا كود في المشروع، لكن يجب ألا يصبح CI «الشيء الذي نبنيه لاحقًا».

## القرار

1. كل Pull Request يمر عبر GitHub Actions بما يلي:
   - فحص المستندات (lint للملفات `*.md`) على الثلاثة: لينكس وويندوز وماك.
   - فحص الروابط في المستندات حتى لا تنكسر الإحالات بين الملفات.
2. وظائف بناء المشروع الحقيقي (سطح المكتب، أندرويد، ويب) تُدرَج من المرحلة 1 على النحو الآتي:
   - سطح المكتب: مصفوفة ثلاثية (ويندوز/ماك/لينكس) مع الاختبارات.
   - أندرويد: بناء تجريبي (debug) بخطوة واحدة للحصول على أسرع زمن للفحوص.
   - الويب: بناء Flutter Web مع اختباراته.
3. الإصدارات النهائية تُبنى فقط من GitHub عبر وسوم (tags) وتُنشر تلقائيًا في Releases. لا بناء يدوي على أي جهاز شخصي.
4. أي ميزة جديدة بدون اختباراتها في نفس الـPR لا تُدمج، وفق AGENTS.md.

## الأسباب

- إعادة البناء على ثلاثة أنظمة تكشف الأخطاء الخاصة بنظام واحد، وهي أخطاء تتجاهلها عادةً مراجعة فرد واحدة.
- الفحص التلقائي للمستندات يحفظ سلامة هذه المرحلة الافتتاحية نفسها، فالوثائق حاليًا هي كل محتوى المستودع.

## التبعات

- ملف الوظيفة يسرد الوظائف المستقبلية كتعليقات معلقة مع شروط تفعيلها، فلا ننسى إضافتها.
- المرحلة 1 تتضمن PR يفعّل الوظائف الحقيقية الأولى.
