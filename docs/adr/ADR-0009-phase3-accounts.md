# ADR-0009: المرحلة 3 — حسابات بكلمة مرور، Supabase حي، ومزامنة محلية أولًا

- **الحالة:** مقبول — بموافقة المالك بتاريخ 2026-11-02 (Issue [#21](https://github.com/kjiu3/farrad1/issues/21))
- **التاريخ:** 2026-11-02

## السياق

[ADR-0008](ADR-0008-local-data-first.md) قسّم العمل زمنيًا: المرحلة 2 محلية بلا إنترنت، والاتصال الحي بـ Supabase يتأجل إلى المرحلة 3 إلى جانب الحسابات. المرحلة 3 الآن مفتوحة بموافقة المالك، ويلزم حسم أربعة قرارات قبل أول PR عملي:

1. طريقة الدخول والتسجيل الأولية (مارست المالك اختيارها صراحة).
2. مكان المفاتيح: الاتصال الحي يحتاج `SUPABASE_URL` و`SUPABASE_ANON_KEY`، وAGENTS §3.1 يمنع كتابتها في المستودع.
3. مصدر الحقيقة أثناء انقطاع الشبكة بعد وجود قاعدة حية: هل تفقد المحلية أولويتها؟
4. من يملك حق الكتابة على التعليق والتقييم ولمن تُعار.

## القرار

1. **الدخول بكلمة مرور (بريد إلكتروني + كلمة مرور):** قرار المالك بتاريخ 2026-11-02، حسمه بدل Magic Link أو الاثنين معًا. الدخول فوري بلا مغادرة التطبيق، ويُدار في PR مستقل (P3-4). كلمات المرور لا تُخزَّن عندنا أبدًا — Supabase (GoTrue) يديرها ويمدد الجلسات، ونحن لا نلمس الرموز إلا ما يمنحه العميل لاستخدام الجلسة. استرداد كلمة المرور المنسية يمر بصندوق البريد عبر مسار إعادة الضبط الذي يوفره Supabase.
2. **المفاتيح عبر متغيرات البيئة فقط:** الاتصال الحي يُبنى على `--dart-define=SUPABASE_URL=…` و`--dart-define=SUPABASE_ANON_KEY=…`، وبملف `.env` غير متتبع في Git للتطوير المحلي. مفتاح `anon` هو العلن مقصودًا؛ الحماية الحقيقية في سياسات RLS على الصفوف لا في سرية المفتاح (بند «أقل صلاحية» في AGENTS §3.4). غياب المتغيرات لا يجهاض التطبيق: يعمل بوضع محلي خالص كما في المرحلة 2، وبانر يبيّن أن الحساب والتعليق غير متاحين بلا اتصال.
3. **بقاء القاعدة المحلية مصدر الحقيقة دون اتصال:** ما طلب المستخدم حفظَه بلا إنترنت يبقى في `RecipeRepository` المحلي (تنفيذ `shared_preferences` من المرحلة 2) كما هو بلا تغيير. كلما عاد الاتصال حصل خلق المزامنة: تعديلات وصفات المستخدم تُدفع حسب الأحدث (`updatedAt` — الأحدث يفوز)، والتعليق والتقييم يكتبان مباشرة للحية لأنهما لا معنى لهما دون حساب. وصفات البذور العشرين للقراءة فقط ولا تُدفَع أبدًا من العميل.
4. **القارئ للجميع والكاتب لمالكه:** قراءة الوصفات والتعليق والتقييم تفتح للجميع (مستخدمًا مجهولًا كان أو مسجلًا) عبر سياسات RLS، والكتابة على التعليق والتقييم قاصرة على مستخدم مسجل معلّقها أو حاقنها، والتقييم رقعة واحدة لكل مستخدم للوصفة (upsert لا تكرار). بهذا يظل مفتاح `anon` قادرًا على القراءة وحدها، وبند الأمان يطابق AGENTS §3.

## البدائل المستبعَدة

- Magic Link: أأمن بلا كلمات لتنقل، لكنه يُخرج المستخدم من التطبيق إلى بريده — اختار المالك تجربة الدخول الفوري.
- الاثنان معًا: مرحلة أولى أثقل بشاشتين ومنطقين في PR واحد، ضد قاعدة «شيء واحد لكل PR» في AGENTS §1.2.
- محلي أولًا ثم حي يفقد المحلية بعد المرحلة 3: يعاقب مستخدمًا بلا إنترنت بفقدان كتابته — ضد غرض التطبيق في الطهي المنزلي حيث الجدار غالب.
- كتابة المفاتيح في `.env` متتبع أو في الكود: مخالفة صريحة لـ AGENTS §3.1.

## التبعات

- أول مخطط SQL للمرحلة 3 (الملفات الشخصية والتعليق والتقييم) يُبنى على هذا القرار: أعمدة مالك لكل تعليق وتقييم، وقيود رقعة واحدة.
- تنفيذ المستودع الحي (تبديل خلف واجهة `RecipeRepository` نفسها) يُختبَر بنفس اختبارات التنفيذ المحلي وفق ADR-0008 §القرار 4.
- كل ميزة حية تُبنى fake-first (اختبارات وحدة بمحاكاة) ثم تُجرَّب حيًّا بعد زوْد المالك مشروعَه بالمفاتيح؛ ما لم يُجرَّب حيًا يُوسَم «لم يُختبر بعد» حرفًا بـ AGENTS §4.1.
- تغيير أي بند لاحقًا يحتاج ADR جديد يغلق هذا — لا تعديل صامت (AGENTS §4.3).
